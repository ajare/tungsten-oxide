## Physics core

C++ independently loads strict schema-10/12 JSON, bakes rational spline paths, emits renderer-neutral geometry, and runs corridor/mesh physics, zones, checkpoints, landing, and recovery.

- **`src/core/`.** Public authored records (`TrackDefinition.hpp`) are separate from the compiled runtime record (`Track.hpp`) and renderer-neutral batches (`TrackGeometry.hpp`). `Track::fromJson()` / `fromFile()` accept schema 10 through 12 (`TrackCore::TRACK_SCHEMA_VERSION_MIN_SUPPORTED`/`TRACK_SCHEMA_VERSION`) and always normalize/write schema 12; 10 remains accepted solely because the golden fixture corpus is permanently pinned at schema 10. `meshAssets`/`meshes` (Mesh regions, removed in schema 12 — `DRIVABLE_MESH_OBJECTS_PLAN.md` Milestone 2) fail to load with an explicit error rather than being silently dropped. `nlohmann/json` remains a private implementation dependency. `fromJson()`/`fromFile()` also take a `detectSelfIntersections` flag (default `true`) gating an O(N²) crossing-detection pass; the editor's live-preview rebake passes `false` mid-drag and reuses its last result.
- **Golden fixture corpus (`src/test-data/`).** The original four baked-world traces isolate runtime math: 4000 steps, `atol=rtol=1e-12`, ratio gate `1e-3`, observed worst `7.322e-5` (1 ULP). Twelve raw-track traces force independent loading/baking and cover 1116 steps of spline and mesh behavior — every one of them references the now-removed `meshAssets`/`meshes`, so the `raw_parity`/`raw_session_init_parity`/`raw_session_step_parity`/`random_geometry_parity` CTest targets that replay them are currently disabled (commented out in `src/core/CMakeLists.txt`) pending Milestone 7's mesh-mode-appropriate replacement traces; the fixtures themselves are left in place as committed history. Both layers include bounded free runs. See `src/test-data/traces/raw/README.md`.
- **Native tests.** `track_tests` covers strict loading, normalization/geometry, and direct simulation scenarios, plus a hard-break check that a `meshAssets`/`meshes`-bearing fixture fails to load with the expected error. `parity` replays the baked-world golden traces above and preserves the physics gates.
- `Vec3` was migrated from a hand-rolled type to `glm::dvec3` (see git history) — the golden fixture tolerances above were re-baselined accordingly at the time. If you see a stale reference to a hand-rolled, pinned Vec3 operation order elsewhere, it predates that migration and should be corrected.
- Track geometry/physics constants of note: `TrackCore::COLLISION_WALL_MARGIN`. The physics centerline sample count is **not** a fixed `TrackCore::N_DEFAULT` — it scales per path with the track's driven length (`TrackBake.cpp`'s `sampleCount()`, holding ~6 m spacing); `N_DEFAULT` is now just the floor and the USD/`track.samples` default. Cross-section width sampling is separately adaptive, not a fixed segment count — see `TrackBake.cpp`'s `crossBreak()`.
- **1 world unit = 1 metre** (see `CONTEXT.md`). `PathHandling::maxSpeed` defaults to 140 (= 140 m/s, 504 km/h); `tungsten-monoxide`'s HUD is a straight `speed * 3.6` → km/h. Authored tracks run 7–10 km; the editor's starter track (a calibrated flat 8 km circle) lives in that regime.
- `Track::fromTrackDataFiles()` (`TRACK_MODEL_LIST_PLAN.md` Milestone 1.2) loads+normalizes N TrackData JSON files independently, namespaces every id each source owns (`"<index>:"` prefix — but never `ModelPlacementDefinition::modelId`, which names an embedded `<Model id>` in the enclosing Track resource's `<Models>` list, an outer-XML concept `core` never resolves) so they can't collide, concatenates their authored lists into one `TrackDefinition`, then bakes exactly once. A single-path call is byte-identical to `fromFile` (no namespacing applied). Currently unused by `src/editor` (which still authors exactly one TrackData file per session) — `src/tungsten-monoxide`'s `Map::load()` is the one real caller, and even it only ever passes one path today, since only one Type=Track `<Model>` is currently supported end to end.
